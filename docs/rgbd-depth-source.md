## 已确认的软件缺陷

本机 `pyorbbecsdk2=2.1.3`、原生 SDK `2.10.6`，在**不创建设备或 Context**的独立进程中构造 `AlignFilter`，实测默认 `TargetDistortion=0`。用 SDK 人工构造的帧及相机参数处理后，输出深度 profile 的八个畸变系数确实全为零。

锁定版本的 [官方 Align.cpp](https://github.com/orbbec/OrbbecSDK_v2/blob/v2.10.6/src/filter/publicfilters/Align.cpp) 同样表明：`TargetDistortion=false` 时输出沿用目标彩色相机内参、绑定零畸变。旧 `OrbbecSource` 没有改这个默认值，却把彩色原始畸变参数放入 Frame；旧 `rectify()` 随后对 RGB 和**已经在理想彩色坐标平面中的深度**一起执行彩色去畸变映射，导致深度多映射一次。

存档参数计算出的最大像素位移：global **3.30 px**、left_wrist **3.36 px**、right_wrist **3.74 px**。这些是映射位移，不是机械臂空间误差或相机外参误差。缺陷会使物体边缘的 RGB 与深度错配；不能用它解释低分 SAM3 为何把整张桌面选成柿子。

已改代码：

- `OrbbecSource` 明确配置 `TargetDistortion=0`，检查 SDK 输出深度的内参与彩色 K 一致且畸变为零，记录 `depth_pixel_geometry=undistorted_color` 与深度帧号。
- `rectify()` 对此类输入只去畸变 RGB，原样复制已对齐的深度；其他声明为 distorted_color 的采集器保持原来的配对映射。
- 不用后处理过滤掩盖坐标错误，不修改外参、单位、分割掩码或机械臂配置。

已有历史深度已被旧映射处理，不能仅补一个 metadata 标记就当作修复，也不能再去畸变一次。应在新流程加载后重新采集验证。**本次修复仅在磁盘，在线仍使用旧流程。**
