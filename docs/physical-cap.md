# 显式授权的单次 CaP 真机实验

**本文件下方为早期实验过程记录。** 其中空夹爪、固定试运动、位移/误差/时效阈值、强制场景、模型碰撞、抓取登记和软件持物一致性要求均已在 2026-11-19 的当前控制入口移除。当前使用方法与剩余条件见 [操作面板](operator-panel.md)。硬件控制异常/未知执行结果仍停止；不自动恢复或 Home。历史失败和测量数据不因策略变化而改写。

实验前通过 `--robot-backend panda_py`（默认）或 `--robot-backend franky` 选择一个控制库；退出实验后才重新选择。两套启动方式、控制路径和软件验证状态见 [后端说明](robot-backends.md)。

默认入口仍不连接真机、不启用运动。只有获得用户对具体物理任务的授权后，才使用 `robol2l_deploy.cap.live`：

```bash
.venv/bin/python -m robol2l_deploy.cap.live \
  --authorize-physical-task --authorization '本次具体用户授权的原文' \
  --codex-model gpt-6-astra \
  --codex-bin .franka-player/tools/codex/node_modules/.bin/codex
```

该入口会实际执行模型生成的代码。它创建唯一的 FR3 / 双相机 Runtime，先验证静止观测、空夹爪、实际 TCP 与模型一致、实时内核与调度权限，然后只为当前进程和指定任务启用动作。配置文件不能启用它；重启不会恢复或重放程序。

抓放任务的首次机械臂动作默认是距观测支撑面至少 15 cm 处、4 mm、姿态不变的离台运动。测得该位移且收据有效后，才允许后续动作。后续仍保留每段 5 cm / 0.15 rad、碰撞、状态/模型/标定绑定、30 秒场景时效、持物状态与低高度释放检查。自动场景只在来源、深度量、支撑法向和时效检查通过后获得本会话的执行资格；没有人工输入目标位置。

单独诊断跟踪时，在已经获得相应动作授权的上述命令中增加 `--task probe --probe-distance-m 0.02`，请求一次 2 cm 离台动作。该任务最多派发一次，不动夹爪，不接续抓放。模型仍从当前观测和状态生成程序；命令中的位移是用户指定的诊断幅度，不是物体位置。4 mm 和 2 cm 模式均检查所请求的法向位移、横向偏差与姿态，不放宽终点验收。

所有动作经过 Runtime。底层库发生异常或终态不能确认时，记录 unknown 并锁住动作；不自动恢复、Home 或重试。会话结束、等待人工或失败后，撤销本次动作权限，工作台保留只读状态。

`panda_py` 保留 libfranka 的强制实时控制。库调用结束后恢复调用线程原有调度策略，防止 Python 图像序列化继承实时优先级而触发系统实时 CPU 限额；不修改系统实时限额。同步轨迹结束后也明确结束 controller 的 running 状态，后续状态读取来自机器人，而非最后一帧缓存。

panda_py 后端使用其原有 PD 刚度 `[600,600,600,600,250,150,50]` 与阻尼 `[50,50,50,20,20,20,10]`，保留 0.003 rad 终点验收。依照 libfranka 关节阻抗示例补充 Coriolis 前馈；重力和电机摩擦由机器人补偿，不重复添加重力。轨迹末端保持目标最多 3 秒，未收敛就返回负收据；增加保持时间不等于纠正静态偏差。控制参数进入计划绑定，变化后旧计划失效。

每次运动记录实际状态、关节参考、速度、力矩、通信指标及 controller 收据，NPZ 位于 SDK 运行目录的 `control-traces`，路径随执行收据归档。参考时间对齐设备的第一个 move 样本，分辨率 1 ms；收据分别保存 native 结束时和随后 Runtime 读取的误差，二者可能因读取时刻不同略有差异。负收据中的步数不作为“未移动”的证据。

2026-11-17 用户根据工程师意见取消负载测定及参数微调方向。此前提出的负载辨识方案不实施，也不作为继续软件诊断的前置条件。现有负载、增益、标定和验收阈值保持不变；负载影响仅保留为未经证实的历史假设，不能写成已定位原因。后续重点核对 panda_py 执行补丁、所选控制接口、参考轨迹与终态反馈及 FR3 兼容性，不启动新的物理实验。2026-11-16 的 2 cm 验证仍失败，不能据此宣称该控制配置已完成物理验收。

实现参考：[libfranka 控制与负载接口](https://frankarobotics.github.io/docs/doc/libfranka/docs/overview.html)、[官方关节阻抗示例](https://github.com/frankarobotics/libfranka/blob/main/examples/joint_impedance_control.cpp)。CaP-X 所指向的 [robots_realtime Franka 实现](https://github.com/uynitsuj/robots_realtime/blob/main/robots_realtime/robots/franka_osc.py) 采用 panda_py AppliedTorque 与 OSC 控制循环，不能据此推断 panda_py 默认关节 PD 已适合当前带腕部附件的 FR3，也不复制其 Panda 模型或碰撞阈值。

完整深度场景的碰撞检查先用 AABB 距离下界排除远离的物体，再以原有 Bullet 精确查询判断接触；支撑面始终检查，持物 AABB 随机械臂更新。余量、采样数与 30 秒观测时效均不变。测试比较空手、持物及多个关节状态下的逐对查询结果。保存的真实 RGB-D 含 1520 个障碍体时，同一 4 mm 规划的软件回放耗时为 1.77 秒（原实现约 33 秒）；这不是物理执行证据。

从固定 URDF 根节点沿固定关节识别基座部件；这些部件与静态观测物体的相对位置不会随轨迹变化，因此不把这种固定—固定配对作为运动碰撞。基座对附着物体、移动连杆对场景、腕部相机对场景及原有自碰撞检查仍有效。

分割投影在深度有效性、边缘腐蚀和局部连续性检查后，移除不足 30 像素的孤立连通域，与单次定位的最少有效深度量一致；保留所有达到阈值的区域，不按物体名称、任务坐标或最大区域挑选。原始 mask、投影 mask、观测编号与删除数量分别保存。完整深度碰撞场景不使用这种语义分割过滤。

任务程序由真实模型生成。验收程序单独检查抓取收据、持物抬升、释放，以及两次静止视觉观测中的盘内包含、夹爪打开和机械臂撤离。程序返回成功、控制收据成功、任务物理成功分别记录。

证据位于 `.franka-player/physical-cap/<session>/hardware`。`/hardware` 工作台可以查看模型源码、反馈并暂停下一次派发；Pause 不是急停。
