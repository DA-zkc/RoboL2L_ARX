2026-11-19 后续更新：已移除强制自动场景、模型碰撞拦截、抓取目标登记和软件持物一致性。感知由 CaP 按需调用；手动移动/夹爪不依赖相机或模型服务。规划明确返回 `collision_aware=False` / `diagnostics.collision_checked=False`，不是碰撞检查通过。设备真实错误或动作结果未知仍停止；不自动恢复/Home。

24 个公共工具、保留规则和硬件差异见 [ASPIRE 对齐清单](aspire-cap-parity.md)。新增 Home、step、关节目标与组合接口已可从“高级工具”调用。

## 日常操作

- **移动**：填写相对当前位置的 X/Y/Z 位移（mm），点击“移动”。读取机器人状态、IK、规划和执行都走公共 API 与唯一 Runtime，不触发感知或建模。“只预览”不执行动作。
- **夹爪**：填写开口宽度（mm），或点“打开”“闭合”。
- **相机**：默认显示 RGB，展开“查看深度”查看深度图。点击“冻结并测量”后，可在图像上点选坐标。
- **断开或换库**：点击“断开”，或顶部“连接 / 换控制库”。在连接页选择控制库后直接连接。
- **CaP**：单独放在“CaP 任务”页。位姿、感知、完整 API 和记录收在“高级工具”。

手动操作不再要求填写授权文字、单独求 IK 或完成一段指定的离台试运动。每次实际点击“移动”或夹爪按钮才派发该动作；连接、刷新页面和“只预览”都不派发动作。硬件错误反馈和故障后停止仍生效；不会自动恢复或 Home。Pause 在下一次派发边界生效。

**Mock 是软件模拟，不连接任何真实机器人或相机。** 它只位于连接页折叠的“开发调试”中，进入后显示明确的模拟横幅，可直接返回连接页切回真机。

## 代码

- `robol2l_deploy/launcher.py`：连接、断开和实验前更换控制库。

## 2026-11-17：控制与感知入口

控制面板支持任意有限 XYZ 位移及完整 0–80 mm 夹爪行程。移除了额外的 50 mm / 0.15 rad 分段上限、关节安全余量、10 mm 碰撞余量、强制试运动、35 mm 释放高度、会话次数/时长和 CaP 修改轮数/API 调用限额。模型/真实关节范围、实际碰撞、控制器错误、失联、暂停与唯一设备 owner 仍有各自含义。控制库负责轨迹时间参数化，未改变控制增益或末端负载。

正常完成的动作返回成功；位置、姿态、关节和夹爪开度偏差单独保留，不锁住下一步。历史记录不改写，只在展示与恢复会话时区分旧精度判定和实际控制异常。中文说明与原始错误码、测量值一起保存。设备控制异常或结果未知仍停止，不自动恢复。

感知页可输入目标描述并点击“一键识别与抓取候选”：自动冻结 RGB-D，运行 SAM3、投影点云、估计几何并调用 Contact-GraspNet。默认使用全局相机，可选择腕部相机。页面显示模型服务是否真实加载、分割覆盖图、候选数量和失败原因。连接真机时自动启动配置中指向本机的两个正式推理服务，缺权重时不会宣称就绪。

模型地址、模型名、思考深度和密钥环境变量名称保存在启动器目录的 `model-settings.json`，设备会话共享，首次从旧启动器配置迁移；切换控制库或重载不再产生空模型配置。服务器环境 `ROBOL2L_MODEL_BASE_URL`、`ROBOL2L_MODEL`、`ROBOL2L_MODEL_REASONING` 仍可提供启动配置。密钥只读取服务器环境，默认变量为 `ROBOT_MODEL_API_KEY`，不会写入共享文件。启动器持有的环境会传给设备会话，切换控制库后仍可使用；完全退出启动器后需由运行环境重新提供密钥，不落盘保存。

## CaP 可调整的运动速度

当前站点的机械臂速度默认建议值是 `0.05`。2026-11-19 按用户删除额外数字限制的要求，取消此前的 `0.1` 上限，使用控制库的原生系数范围 `0 < s <= 1`。配置位于 `config/station.json` 的 `motion.default_speed_factor` / `motion.max_speed_factor`，两后端一致。

CaP 沿用 RoboL2L 的规划签名和 `MotionStrategy` 构造器，不新增控制接口：

```python
strategy = MotionStrategy(ik_solver="station", pose_planner="station",
                          time_dilation_factor=0.05)
plan = plan_motion(goal, strategy=strategy)
if plan.ok:
    result = execute_trajectory(plan.trajectory)
else:
    result = plan.error
```

`station` provider 将本次规划的 `time_dilation_factor` 映射到控制库的速度系数，较小值较慢，最终时间以 `plan.diagnostics.duration_s` 为准。省略策略使用默认 `0.05`，AI 可选择原生范围内的系数。零、负值、非有限值及超过原生范围的值返回 `invalid_request`。参数只影响本次规划的机械臂轨迹，不修改下一次规划的默认值、夹爪速度、负载、控制增益或碰撞设置。

面板顶部显示默认值和控制库最大系数，规划结果及 CaP 调用卡片显示本次实际系数和计划时间。系数变化与实际运动耗时并非线性关系。较早的离线历史路径重算中，franky 示例路径在 `0.01/0.05/0.1` 下分别约 `53.52/24.05/17.07` 秒；panda_py 同一路径约 `21.14/4.35/2.25` 秒。记录位于 `runs/harness-verification/speed-planning-franky.json` 与 `speed-planning-panda_py.json`，不代表本轮的实机运动验证。

## 2026-11-19：删除数字门槛后的剩余条件

当前面板及 CaP 使用 `robol2l_deploy` Runtime；历史实验脚本及未接入该入口的旧执行器不是当前控制通路。已移除起点关节/速度/夹爪偏差、终点误差、FK/IK 残差验收、计划/观测/场景时效、持物开度漂移、感知置信度/点数/深度裁剪、障碍数量和代码/请求大小等项目门槛。偏差、时间和原始反馈继续保存。真实任务的数字评分不再阻止 AI 报告完成，界面标注“AI 报告完成”，不据此宣称独立验证了物理成功。

以下为移除自动场景、模型碰撞、目标登记与软件持物一致性后的剩余条件：

| 条件 | 当前行为 | 所属层 |
| --- | --- | --- |
| 类型及设备身份 | 不要求计划登记或单次使用，不因旧观测引用拒绝；仍校验机器人型号、关节名称及输入类型 | 公共契约 |
| 设备状态与通信 | 非 idle、真实控制器错误、FCI/实时条件或设备通信不可用时不能执行 | 驱动及项目入口 |
| 暂停与运动启用 | 暂停、未启用运动、授权会话已结束时不派发 | 项目会话管理 |
| 异常锁存 | 原生控制失败、缺少可信终态收据或执行结果未知会停止后续动作；已知未夹住属于可修订反馈，不因软件持物推断锁存 | 项目执行管理 |
| 串行与重启 | 同时只能有一个操作；不积压运动队列；忙时不切后端；重启不续跑 | 项目设备所有权 |
| 支持范围 | 24 个公共工具在 `primary` 单臂接通；支持 Pose、关节目标、Home、step、组合接口与 timing 参数；无第二只实体手臂，未配置求解器仍如实报错 | 硬件与配置 |
