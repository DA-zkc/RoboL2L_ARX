# ARX 手动摆位与锁位恢复

2026-11-24：代码与软件验证完成，**未部署，未做真机验收**。用户当前实验继续运行；本次没有暂停、停止、清故障、重启服务或发送真机动作。

## 日常入口

控制面板和实机实验页都有“手动摆位与锁位恢复”，无需进入手眼标定或创建批次。

1. 选择左臂或右臂，点击“10 秒后手动摆位”。点击即授权本次单臂手动引导，不另弹开始确认框。Runtime 保留当前控制目标并倒计时，操作者利用这 10 秒去持稳所选臂；可以取消倒计时。
2. 倒计时结束后，检查当前设备状态，通过现有 SDK `gravity_compensation()` 进入重力补偿。页面显示“可以手动摆位”后引导机械臂。不需要持续按鼠标，没有 30 秒或其他自动结束时限。
3. 摆好后点击“锁定当前位置”。按所选臂当时实测位置发送 JOINT 目标，再检查反馈。另一臂和夹爪不接收摆位指令。锁位结束后程序运动权限关闭，不自动回 Home、继续实验或重设初始快照。
4. 若本次示教锁位反馈未通过，页面直接显示“复验当前位置锁位”。现场重新确认两臂已支撑后才执行一次复验。原生故障、失联和未知命令结果不被当成普通反馈失败清除。

倒计时和拖动由 Runtime 工作线程持有独占租约，不由浏览器定时器触发。换页、失焦或刷新不会结束已开始的拖动；重新打开两个入口都能看到状态并锁位。控制台本身暂停、关闭或出现故障会请求退出锁位。控制台进程失联时，升级后的 resident owner 在原有 3 秒客户端租约失效后对已登记示教臂请求锁位，并记录真实结果；这不是 3 秒拖动时限。owner 崩溃、断电或 CAN 故障仍不构成姿态保持保证。

实验仍有未结束记录但正在等待人工时，可以使用这些入口，不必结束实验；实验/CaP 执行线程正在运行时仍不能争用同一硬件。操作会写入 Runtime 事件及当前实验的人工干预记录。手动摆位和“授权自动复位并继续”是不同操作，后者仍遵循原实验流程。

## 本次查到的问题

- 原“解锁机械臂”实际调用 `Runtime.unlock()`→`adapter.recover()`。双 ARX 无 `recover()`，它从来不是手动引导。现在 ARX 隐藏该不支持按钮；其他后端文案明确为“恢复控制器故障”。
- 旧入口依赖标定批次、按住使能键、0.65 秒心跳和 30 秒上限，无法满足单人离开鼠标再扶臂的操作。新入口不依赖批次、按键或浏览器心跳；旧按住示教路径保留其释放/失焦逻辑，但也取消固定 30 秒上限。
- 迁移常驻 owner 后，原复验只设单侧 `driver.allow_motion=True`，未向 owner 授权，owner 会拒绝锁位 RPC。修复为在独占租约内经双臂适配器同步 owner 权限，只向故障侧发送锁位，最后撤销权限。**这不是迁移前那次历史失败的原因。**
- 原 owner 失联保护只处理 JOINT 模式，不能退出 GRAVITY。现登记重力补偿派发（包括返回未知），租约丢失时对该侧走已验证的锁位流程。遇到 SDK 原生故障或非 JOINT/GRAVITY 模式不强制恢复，也不使用 damp/protect/断开。
- 原锁位循环用分别读取位置、速度及 FK 的完整机器人状态做约 50 ms 采样，且只保留最后一次误差和速度，无法区分速度尖峰、采样间隔超限和反馈未更新。现在使用单次 SDK `get_status()` 读取 q/v/mode/cycles，避免循环中的分散 RPC 和 FK；记录各次 q/v、间隔、模式、控制循环计数、overruns、loop_dt_max、命令耗时和窗口重置原因。SDK 有 cycles 时，重复/倒退的 cycle 不计入稳定窗口。成功与失败都保存样本。

## 历史失败能证明什么

证据来自原 `events.jsonl` 和 `20261124-perception-load/left-teach-*.json`，没有重新操作真机。

失败前两次示教锁位都成功。失败那次 `teach_dispatch` 为 1795525279.609951，`outcome_unknown` 为 1795525283.7210903，间隔约 4.111 秒；锁位反馈循环本身最多等待 4 秒。因此时序与“进入后很快退出示教，再等待锁位验证失败”相符，不能将它解释为正常拖动超过了 30 秒。旧记录没有松键、失焦、心跳到期或锁位请求时间，无法进一步确定退出触发原因。

最后一次位置误差 0.00458 rad 在原 0.01 rad 阈值内；J2 速度 0.11868 rad/s 超过 0.025 rad/s，最长连续稳定窗口 0.458 秒不足 0.5 秒。可确定是**锁位反馈条件未满足**，不能确定是手的运动、实际机械振动、反馈尖峰还是采样时序导致。首次复验的 409 只说明预检没通过，未派发新保持；有同伴后复验成功，也不能反推前次一定是操作者扶不稳。

位置 0.01 rad、速度 0.025 rad/s、稳定 0.5 秒、间隔 0.15 秒及等待 4 秒均未放宽。软件改进消除了已确认的接口/时序观测缺陷，但真实物理成因仍需后续现场采样辨别。没有把软件模拟说成消抖或承重验收。
